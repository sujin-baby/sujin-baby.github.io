## 4. 최근 바뀐 것 (10/26 ~ 10/30)

### 관리 시스템 (`ori/Main.js`)
- **장바구니건**: 한 사람이 상품 N개를 한 번에. 진행목록 인원·폼 마감은 **사람 수**, 방제·명단 시트 이름·한눈에·월급시트는 **물건 수(사람 × N)**. `CART_<시트ID>` 속성. 결제금액 확인은 상품 가격 합계. 명단방 글 끝에 `장바구니건`. 방제 끝 숫자 → 목표인원은 ÷ N.
- **결제금액 확인**: 폼 보기 가격 → 장바구니 합계 → 기억한 옵션 가격(`OPTPRICE_<시트ID>`, 배정 저장 때 기억 — 사용자가 배정 줄을 날마다 지워도 됨) → 같은 옵션 다수 금액 순. 기준을 못 찾으면 '확인 필요'로 할 일.
- **모자란 날**: 다음 날 진행이 모자란 것만이면 그 옵션·개수로 공지, 명단방 글에 `구매요청N건 진행N건 잔여N건 / [내일 구매로 진행] / 옵션>잔여N건` (10.28 진행부터). 공지(폼 설명)가 비면 다음 날 진행을 만들지 않고 할 일 한 번.
- **명단방 글**: 전날과 공지 가격이 다르면 `가격변동 9100 > 9200`.
- **배정 읽기**: 대괄호 안에 'N명'이 있으면 배정 줄로 읽음, 구분선 없는 여러 상품 공지는 상품마다 나눠 읽음.
- **리뷰 가이드**: 명단이 바뀌면(중복 삭제·늦게 낸 사람) 대기 중인 가이드를 다시 만듦(손으로 고친 건 그대로). 옵션(색상)마다 포토 1명(`RV_.photoPerOpt`), 줄 설명(`lineNote`).
- **기대평(백발백중)**: `EXP_MIX`/`EXP_WHO` — 2주차 = 1주차 같은 요일 같은 계정이 반대 묶음. 진행시간 `자정 ~ 오전 8시 20분`.
- **경고 잠금**: 자동 칸(배정 E·F·G, 보낼메시지 A·C, 진행목록 인원·마감 시각·숨김 ID, 월급시트 수식 칸)에 '경고만' 보호.
- **한눈에**: 명단 덩어리는 처음부터 목표 + 3줄 자리(응답이 몰려 다음 덩어리에 막혀 `#REF!` 나던 것). 피클의 in-place 갱신(통째 지우기 없음) 위에, **덩어리마다 자기 자리만 지우고 씀**(10/30).
- (피클) 15분 확인에서 어제 이전에 마감·구매시간 끝난 진행은 건너뜀(늦은 응답은 9시 현황 업데이트와 폼 제출 트리거가 셈). 목표인원 고칠 때 `onAdminEdit` 동작. 즉시 마감 패스트트랙, 2일 지난 보냄 메시지 정리, 보낼메시지 중복 방지·오늘/내일 먼저 정렬, 리뷰 보고 양식(폴더 링크). `payCarry_` 이월 줄 정리: 월급시트 전체를 아래서부터 훑어 유효하지 않거나 중복인 이월 줄을 자동 삭제하고, 당월 진행이 이미 있는 캠페인(`inMonthKeys`) 및 종료/취소된 체인은 이월 대상에서 원천 제외(10/30: 11/2 백발백중 진행이 있음에도 10/26 옛 종료 체인 때문에 이월 줄이 되살아나던 버그 영구 패치). ⚠ 돈 관련 행을 다루므로 결과는 꼭 눈으로 확인.

## 5-1. 에이전트 두 명(Claude Code · 피클)이 같이 일할 때

- 둘은 직접 연결이 안 됨 → **이 파일이 연락 창구**. 작업을 시작할 때 `git pull` 후 이 파일부터 읽고, 끝나면 "최근 변경"과 "남은 일"에 적고 push.
- 같은 때에 둘이 `ori/Main.js`를 고치면 충돌이 남 → 한 명이 작업 중이면 다른 한 명은 기다리기. push 전에 꼭 `git pull`(merge) 후 시험 다시 돌리기.
- 사용자 결정은 아래 "남은 일"에 ✅/❌로 남김 → 다른 에이전트가 다시 묻거나 다시 제안하지 않게.
